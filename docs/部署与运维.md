# 部署、迁移、归档与恢复

更新日期：2026-10-22。适用单台 Linux Docker 主机；Windows 可通过 Docker Desktop 的 Linux 容器演练。所有运维脚本要求 **PowerShell 7.4+（pwsh）**，与兼容 Windows PowerShell 5 的演示初始化脚本区分。以下命令均从仓库根目录执行。

## 数据库版本

第六批起由 Spring Boot 集成 Flyway 统一建表和升级，版本由现有 Spring Boot 依赖管理固定。迁移在词库读取前执行，失败会阻止应用启动。

| 文件 | 用途 |
|---|---|
| `speakToMe-app/src/main/resources/db/migration/V1__initial_schema.sql` | 冻结第五批的 11 张表结构；空库自动执行，生产不写演示业务数据。 |
| `V2__audit_log_nullable_review.sql` | 允许本地预检拦截时审核日志没有 review_id；历史记录与其余字段保留。 |
| `db/demo/R__example_data.sql` | 只在独立 demo 加载；按固定 ID 补齐示例，重复执行不覆盖已维护记录。 |
| `sql/init`、`sql/schema.sql` | 历史初始化材料，不再由 Compose 自动执行，不可用于增量升级。 |

已发布迁移不可修改。新增版本使用新的 V 编号；checksum 不一致、非空但无版本历史、SQL 错误均应停止发布并调查，不能运行 repair、clean 或删历史表来强行通过。MySQL DDL 不能保证事务回滚，失败迁移必须由维护者核对实际结构并准备修复方案。

### 空环境

演示环境按[快速开始](快速开始.md)初始化 `.env` 后 `docker compose up -d --build --wait`；MySQL 健康检查只要求数据库可连接，应用负责建表。生产环境按下一节操作，不写演示校区、菜品或账号。

### 第五批存量库接管

先保留原 `.env`、AES 密钥、镜像与数据卷；构建第六批固定版本镜像。运维命令中的 Compose 文件、项目名和 env 文件必须指向原有数据卷，不能因为换项目名而误连空库。不要将 demo 的数据卷直接用作生产库。

以下以原有本地 demo 项目为例；将 `原项目名` 替换成 `docker compose ls` 中实际名称。`.env` 追加 `APP_IMAGE=speaktome:batch6-你的提交号`，不修改已有密码和 AES_KEY。

```powershell
docker build -t speaktome:batch6-你的提交号 .
pwsh -File scripts/ops.ps1 -Action Backup -ComposeFile compose.yaml -EnvFile .env -Project 原项目名 -BackupDirectory backups/接管前
docker compose -p 原项目名 stop app
pwsh -File scripts/ops.ps1 -Action Baseline -ComposeFile compose.yaml -EnvFile .env -Project 原项目名 -BackupDirectory backups/接管前 -ConfirmLegacySchema
pwsh -File scripts/ops.ps1 -Action Deploy -ComposeFile compose.yaml -EnvFile .env -Project 原项目名 -Image speaktome:batch6-你的提交号 -BackupDirectory backups/升级前
```

接管会使用数据库管理员创建随机参考库，执行 V1 后比较表、列、类型、默认值、可空性、字符集、索引及约束；忽略数据量和自增计数。结构不匹配、已有历史表、缺少配套备份时拒绝接管；只清理自己创建的参考库，不清理目标库。成功仅记录 V1 基线，应用启动再执行 V2。完成后一次性管理员容器退出，常规应用仍使用业务数据库账号。

生产存量库如果有超过 61 天的审核日志，先在应用保持停止、已完成备份的维护窗口，用新镜像执行 `Archive`（每次最多 500 条，按输出重复直到没有过期记录），再执行 Deploy。否则归档积压会使新版本 readiness 失败；不要临时禁用积压检查来跳过留存处理。demo 默认不启用该积压检查。

遇到结构差异应先保存查询结果、与 V1 人工比较，再另行制定迁移；本脚本不会猜测如何修复使用者的自定义数据库。

## 单机生产部署

生产使用独立的 `deploy/compose.prod.yaml`，不要与 demo Compose 叠加。准备自己的微信 AppID/AppSecret、合法 HTTPS 域名与证书：

1. 复制 `deploy/prod.env.example` 为 `deploy/prod.env`，填写所有必填值；密码和 AES 使用不加引号、不含变量引用的随机 Base64。AES_KEY 必须是 32 字节随机值的 Base64，创建业务数据后保持稳定。
2. 将证书完整链放在 `deploy/certs/fullchain.pem`，私钥放在 `deploy/certs/privkey.pem`。这些文件与 prod.env 已忽略。限制主机上文件访问权限，不在共享目录或公共 CI 中放生产配置。
3. 构建并分发固定提交标签或镜像摘要；脚本要求镜像已在本机，并拒绝 latest。首次部署可使用 `docker build -t speaktome:固定提交号 .`，远端镜像应先拉取并核对摘要。
4. 设置 prod.env 的 APP_IMAGE 与待部署镜像一致。运行下列部署和检查命令。

```powershell
pwsh -File scripts/ops.ps1 -Action Deploy -Image speaktome:固定提交号
pwsh -File scripts/ops.ps1 -Action Check
```

生产只公开 Nginx 80/443；数据库、Redis、应用和管理端口都不映射宿主。Nginx 覆盖外部代理头，Tomcat 仅信任模板中的 Nginx 地址 `172.30.122.10`。若该网段与现有网络冲突，需一起修改 Compose 的子网、Nginx 固定地址及应用的受信代理正则，并重新验证，不能仅改其中一项。历史 `deploy/nginx.conf` 面向特定 CDN 白名单，保留参考，当前生产模板不使用它。

应用以非 root、只读根文件系统运行，只有临时目录及归档卷可写；停止时最多留 40 秒等待请求结束。容器标准输出按 10 MB × 3 轮转。Nginx 当前关闭访问日志以避免记录请求凭证；启用时应使用经过脱敏的格式。

这里交付的是单机模板，未提供高可用、托管证书签发或真实云账号部署。自签证书只用于自动演练，不能用于正式微信客户端。真实微信与设备验收仍按[第五批说明](第五批功能与验收说明.md)补齐。

## 审核日志归档

- 每天上海时间 02:00 运行，保留至少 60 天。每批默认 500 条，每次最多十批，避免长事务；积压超过保留期限一天会让 readiness 报告失败。
- 事务用行锁和 SKIP LOCKED 取得一批日志，序列化为 UTF-8 JSONL，文件 fsync、SHA-256 回读校验和校验文件落盘完成后同步目录，最后只删除本批 ID；任何失败都回滚数据库删除。
- 目录权限 700、文件权限 600。生产文件在 `/app/archive` 的持久化卷中。归档依赖 Linux/POSIX 的文件与目录同步语义；Windows 宿主请使用 Linux 容器，原生 Windows 目录不支持时保留原数据并报错，绝不跳过持久化步骤。
- 文件已写而数据库事务失败时可能产生重复文件，按原始日志 id 去重即可；失败时遗留的不完整文件没有校验文件，不可当成有效归档。不会自动删除归档或备份。
- JSONL 含审核文本和用户编号，是敏感业务材料。归档卷只是本机持久化存储，不是异地备份；必须随备份加密保存到受控异地介质。磁盘与文件系统本身的持久性由部署者保障。

手动处理一批（不启动 Web 或业务定时任务）：

```powershell
pwsh -File scripts/ops.ps1 -Action Archive
```

demo 默认不自动归档，但手动命令仍可在独立测试环境验证。`AUDIT_RETENTION_DAYS` 不得低于 60；如果调整 Compose 的保留期，归档任务与健康检查应使用同一配置。

## 备份与空环境恢复

备份期间会暂停当前应用写入，完成后恢复原应用状态。维护者必须同时停止其他实例、人工 SQL、定时写入和外部 Redis 写入者；脚本只能控制指定 Compose 项目的 app，不能替代多实例维护窗口。

```powershell
pwsh -File scripts/ops.ps1 -Action Backup
```

默认位置为 `backups/项目名/时间-随机后缀`，指定 `-BackupDirectory` 时必须是不存在的新目录。备份包含 MySQL 全库逻辑转储（含 Flyway 历史）、Redis RDB 快照、归档文件，以及 SHA-256 清单、来源项目/镜像与 AES 指纹。不会复制 `.env` 或 AES 密钥；密钥、密码和部署配置必须通过独立的受控渠道配套保存。清单只能检测意外损坏，不替代可信来源或签名。

Linux 自动限制备份目录为 700；Windows 请另设只允许备份账号访问的 NTFS 权限。备份是明文，不得上传 Git、共享网盘或普通 CI 产物。生产应使用主机/存储加密，按自己的保留策略转存异地并定期做恢复演练。

恢复只接受**新项目中的空 MySQL、空 Redis、空归档卷**，并要求目标配置的 AES_KEY 与备份指纹一致：

```powershell
# 准备独立环境配置，填入配套 AES_KEY、自己的密码与备份对应镜像；先只启动数据库和 Redis。
docker compose -p speaktome-recovery --env-file deploy/recovery.env -f deploy/compose.prod.yaml up -d --wait mysql redis
pwsh -File scripts/ops.ps1 -Action Restore -Project speaktome-recovery -EnvFile deploy/recovery.env -BackupDirectory backups/待恢复目录 -ConfirmRestore
```

恢复将校验清单、导入 MySQL、复制归档，并让 Redis 从 RDB 加载后重建 AOF。应用保持停止。先核对版本、行数、中文数据、归档、历史 openid 的可解密性和会话，再启动配套镜像及代理。恢复同一主机时不要同时启动两个生产模板的 Nginx 固定网段；正式灾备优先使用独立主机。

恢复中途失败时目标可能已有部分数据；保持停止并保留排错信息，另建空环境重新恢复。脚本不会清空失败目标或覆盖现有数据。副本恢复会复制账号角色与会话，必须限制副本网络访问；需要失效会话时应由维护者明确执行，不自动修改备份数据。

## 发布与回滚

`Deploy` 在存在旧应用时先备份，然后等待新应用健康，再重建 Nginx 重新解析上游并检查 HTTPS，成功才写入忽略的 `var/ops/项目名/deployment.json`；失败尝试恢复旧应用镜像，同时返回失败退出码。如果备份失败，不进入发布。首次部署没有旧镜像可退，失败时保留容器和日志。

```powershell
pwsh -File scripts/ops.ps1 -Action Deploy -Image speaktome:下一个固定提交号
pwsh -File scripts/ops.ps1 -Action Rollback
```

Rollback 同样先备份，只切换到记录中的上一版镜像，不执行数据库逆向迁移。未来迁移必须采用先扩展后收缩并明确兼容窗口；如果旧应用不兼容新结构，回滚前必须另行使用配套备份在空环境恢复。第六批 V2 只放宽空值，不删表/列。

镜像状态文件只记录标签，使用者必须保证发布标签不可变；生产优先使用 `镜像名@sha256:...`。不要删除仍处于回滚窗口的镜像和备份。第五批旧应用仍有直接清理历史日志的定时任务，不宜长期回退运行。

## 健康监控与计划任务

管理服务只监听容器内 127.0.0.1:9001，暴露 health/metrics，健康响应不展示组件细节。liveness 只反映进程状态；readiness 还检查数据库、Redis、磁盘及归档积压。故障会让 Docker 健康状态异常并使 `ops.ps1 -Action Check` 返回非零；Docker 本身不会因 unhealthy 自动重启应用。

```powershell
pwsh -File scripts/ops.ps1 -Action Check
docker compose --env-file deploy/prod.env -f deploy/compose.prod.yaml exec -T app curl --fail --silent http://127.0.0.1:9001/actuator/metrics
```

在自己的 cron、systemd timer 或 Windows 计划任务中设置每分钟执行 Check、每日执行 Backup，并把非零退出码接入现有告警平台。示例 Linux cron（替换仓库路径与 pwsh 路径，日志目录预先创建并限制权限）：

```cron
* * * * * cd /srv/speakToMe && /usr/bin/pwsh -NoProfile -File scripts/ops.ps1 -Action Check >> /var/log/speaktome-health.log 2>&1
30 3 * * * cd /srv/speakToMe && /usr/bin/pwsh -NoProfile -File scripts/ops.ps1 -Action Backup >> /var/log/speaktome-backup.log 2>&1
```

本仓库不擅自创建主机计划任务或向邮件/聊天工具发消息；外部通知接入、磁盘告警阈值、日志轮转、证书到期监控、异地备份任务和保留策略由生产维护者配置。实际 RPO/RTO 应通过目标部署环境测量，不能使用 CI 耗时承诺生产恢复时间。

## 自动演练

```powershell
docker build -t speaktome:运维验收 .
pwsh -File scripts/smoke-ops.ps1 -Image speaktome:运维验收
```

该脚本只创建 `ops-随机ID-*` 独立项目，使用虚构微信配置和本地自签证书，验证存量接管升级、归档、数据库/Redis/归档恢复、错误密钥和损坏备份拒绝、非空目标拒绝、镜像切换与失败恢复、生产 HTTPS、端口隔离及依赖故障探针，最后删除这些测试项目及其测试数据卷。它使用同一应用包构造不同镜像 ID 来验证发布控制流程，不替代每次真实历史版本的业务兼容性回归。
