# 数据字典

核对日期：2026-10-24。结构来自 Flyway V1 + V2 的累积结果，包含 11 张业务表；`flyway_schema_history` 由 Flyway 管理，不手工修改。所有表使用 InnoDB、utf8mb4、utf8mb4_unicode_ci，主键为自增 BIGINT UNSIGNED。表之间用逻辑 ID 关联，未建立数据库外键；不能依赖数据库自动级联删除。

应用实体使用 camelCase 映射下划线字段。下表的“可空”和默认值描述数据库约束，不等同于接口可写字段；API 可能有更严格限制。自增列无普通默认值，省略时由数据库生成。除 audit_log 外，所有业务表有 created_at 与 updated_at，后者由数据库 ON UPDATE CURRENT_TIMESTAMP 更新。

## 表关系与使用状态

| 表 | 用途与逻辑关联 | 当前状态 |
|---|---|---|
| campus | 校区 | 已使用 |
| user | 用户；campus_id → campus | 已使用；unionid、手机号为预留 |
| site | 美食地点；campus_id → campus | 已使用；封面和地点评分聚合未接通 |
| stall | 档口/店铺；site_id → site | 已使用 |
| dish | 菜品；stall_id → stall | 已使用 |
| review | 点评；user_id → user，food/dish 时 target_id → dish | 菜品点评已使用，其他目标类型未实现 |
| audit_log | 审核快照；user_id → user，review_id → review，可为空 | 已使用并归档 |
| report | 举报；review_id → review，reporter_id / handler_id → user | 已使用 |
| sensitive_word | 本地审核词库 | 已使用 |
| post | 通用内容；user_id → user | 预留，无对应业务接口或页面 |
| trade_order | 订单；post_id → post，buyer_id / seller_id → user | 预留，无交易流程 |

V1 中关于后续模块、“零 DDL 复用”和“24 小时处理”的注释不代表已交付能力或服务承诺。结构调整必须新增迁移，禁止修改已发布的 V1/V2。审核下架使用 audit_status=2；用户删除使用 is_deleted=1，二者不同。

## 业务状态与约束

- user.role：0 普通用户，1 管理员；user.status：1 正常，0 封禁。数据库存在账号不代表会话及全部业务权限都有效。
- site.site_type：1 校内食堂，2 校外区域，3 其他。对象 status=0 不会级联改写子对象。
- dish.is_available：1 在售，0 下架；和对象 status 的启停是两个字段。
- review.audit_status：0 待审核，1 通过，2 拦截，3 人工复审。只有 food/dish、审核通过且未删除的点评进入菜品评分。
- audit_log.check_type：1 本地敏感词，2 微信；risk_level：0 正常，1 嫌疑，2 违规；result：1 放行，0 拦截，不等同于 review.audit_status。时间列是 **create_at**，不是 created_at。
- report.status：0 待处理，1 已处理，2 驳回；reason_type：1 垃圾广告，2 色情，3 辱骂，4 政治敏感，5 学术不端，6 其他。
- sensitive_word.category：1 政治，2 色情，3 辱骂，4 广告，5 学术不端，6 其他；level：1 直接拦截，2 人工复审。不要与举报原因枚举混用。
- openid 使用 AES-256-GCM 密文保存，并以 SHA-256 摘要查询。恢复数据时必须使用配套 AES_KEY；密文及原文都不应进入公开截图、日志样例或导出的示例数据。

## Redis 键与缓存边界

| 键 | 类型与内容 | 有效期/更新方式 |
|---|---|---|
| `session:{token}` | String，用户 ID | 默认 7 天，不滑动续期；单 token 撤销已有方法，批量撤销未实现 |
| `rate:login:{ip}` | 限流计数 | 60 秒窗口，最多 5 次 |
| `rate:comment:{userId}` | 点评限流计数 | 60 秒窗口，最多 5 次 |
| `rate:report:{userId}` | 举报限流计数 | 60 秒窗口，最多 5 次 |
| `report:dup:{reporterId}:{reviewId}` | String，举报去重标记 | 24 小时；提交事务异常时尝试移除 |
| `food:dish:{dishId}:stat` | String，1—5 星人数 JSON | 30 分钟；评分刷新后删除缓存 |
| `rank:hot:dish:{days}` | ZSET，member=dishId，score=hotScore | 7/30 天榜单每十分钟重建，没有单独 TTL；重建非原子 |
| `wx:access_token` | String，微信服务端调用凭证 | 缓存 7000 秒；失效响应触发清理，下一次请求刷新 |

榜单热度为 `ROUND(近期通过且未删除点评数 × 2 + 近期平均分 × 10, 2)`，没有额外的三天权重。命中 Redis 后仍查询 MySQL 组装条目。微信 access_token 由内容审核客户端缓存，和用户会话 token 不同；不同小程序的后端不要共享同一个 Redis 逻辑库。

## 升级与归档

新增字段时增加 V3 及后续迁移，同时修改实体、接口和本文；存量无版本库须先结构核验再接管。不要运行旧 sql/schema.sql 升级生产数据。过期审核日志先写入持久化 JSONL 和校验文件，成功才删除数据库记录，归档也需要备份与访问控制。具体步骤见[部署与运维](部署与运维.md)。
