## 第二批实现与接口

- 个人中心每次进入刷新用户资料和校区名称；支持昵称保存并同步本地用户缓存，复用已有资料接口。头像仅展示，未增加上传功能。
- 校区修改复用现有选择页，保存后返回美食页；再次进入个人中心会显示最新校区。
- 主题设置复用全局方法，支持跟随系统、日间、夜间三种模式并保存偏好。
- 新增 `GET /api/v1/reviews/mine?page=1&size=10`，必须登录。`page` 至少为 1，`size` 为 1—50；用户身份来自登录上下文，不接受客户端指定查询其他用户。
- 响应使用既有统一格式，`data` 包含 `list`、`total`、`page`、`size`。每条记录包含 `id`、`dishId`、`dishName`、`rating`、`content`、`auditStatus`、`createdAt`。
- 查询仅包含本人、`food` 模块、菜品类型、未删除的点评；不按审核状态过滤，保留本人查看全部审核状态的能力。按发布时间及 ID 倒序，保证同一时间的分页顺序稳定。
- 分页内批量读取菜品名称；菜品记录已移除时显示“菜品已移除”，仍允许管理该条历史点评。
- 删除复用 `DELETE /api/v1/reviews/{id}`，确认后执行，由后端校验归属并维护原有评分汇总；成功后从第一页重载，避免删除造成列表偏移。分页请求失败保留原有列表及页码，供手动重试。
- 本批新增的业务注释标注“10/15”。
