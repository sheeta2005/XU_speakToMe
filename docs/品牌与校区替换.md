# 换成自己的学校

这个项目没有品牌生成器，也不用全局替换包名。先改界面名称和业务数据，确认能跑通后再考虑工程重命名。

## 名称、主题与域名

| 位置 | 修改内容 |
|---|---|
| `miniprogram/app.json` | `window.navigationBarTitleText`，默认“西邮点评家”；Tab 名称在 `tabBar.list` |
| `miniprogram/pages/auth/login.wxml` | 登录页显示的项目名称 |
| `speakToMe-user/src/main/java/com/xiyou/speakToMe/user/dto/UserVO.java` | 用户资料没有昵称时的“西邮同学”回退文本 |
| `speakToMe-canteen/src/main/java/com/xiyou/speakToMe/canteen/service/ReviewService.java` | 评论作者没有昵称时的“西邮同学”回退文本 |
| `miniprogram/app.wxss`、`miniprogram/theme.json` | 页面颜色与导航栏的日间/夜间配色；两套主题都要检查 |
| `miniprogram/config.js` | develop、trial、release 的接口地址；正式接入时 develop.demo 改为 false |
| `miniprogram/project.config.json` | 微信开发者工具的 AppID、项目名称；不要上传个人本地设置 |
| `.env` 或 `deploy/prod.env` | 后端的 WX_APPID、WX_SECRET，与前端 AppID 对应；保留与历史数据配套的 AES_KEY |
| 微信平台后台 | 自己的接口合法域名；正式域名和可信证书需由部署者配置 |
| `README.md`、`pom.xml` 的名称/描述 | 项目展示信息；业务包名和 Maven 坐标可以先保持原样 |

当前没有独立 Logo 图片、品牌配置中心或静态资源上传服务。不要在仓库里填写真实 AppSecret、证书私钥或用户数据。部署方式见[部署与运维](部署与运维.md)。

## 初始化自己的校区

正式环境不加载示例校区。推荐使用独立的 prod 数据库和 Redis，顺序如下：

1. 按[快速开始](快速开始.md)完成真实微信配置并启动；应用自动执行 Flyway 迁移。
2. 用自己的微信身份登录，从 `GET /api/v1/auth/me` 核对用户 ID。没有校区时先完成管理员初始化，不必伪造校区编号。
3. 按快速开始的“首次真实管理员”说明提升这个已存在的账号，再重新进入个人中心。
4. 管理工作台 → 对象维护，依次创建校区、地点、档口、菜品；地点归属校区，档口归属地点，菜品归属档口。
5. 普通用户选择新校区，检查列表、详情和点评；管理员复审后检查评分与榜单。

对象由接口返回的实际 ID 关联，不要求从 1 开始。不要直接修改其他校区的 ID，也不要把 demo 用户和数据卷搬进生产环境。校区选择接口目前只校验正整数，未验证校区存在且启用，客户端应从校区接口选择；这是待补的服务端校验，不是可依赖的权限控制。

### 只想改本地演示数据

可直接通过管理页修改已有对象。`db/demo/R__example_data.sql` 按固定 ID 补缺，不会覆盖维护后的同 ID 数据，因此修改已有演示内容应走管理页。需要修改模板默认种子时，只改 demo 重复迁移，并在全新测试数据库验收；已有库不会因此重置已有记录。

不要改 `V1__initial_schema.sql`、`V2__audit_log_nullable_review.sql`，包括其中的历史学校名称注释。它们已发布，有校验和；结构变化只能新增迁移。`sql/init` 是历史材料，不是当前初始化入口。

## 替换后的自查

- 登录页、导航、空昵称评论没有遗留学校名称；日间和夜间都能看清文字。
- 开发版连接自己的测试接口，体验/正式版连接自己的 HTTPS 接口并关闭演示入口。
- 新校区可以进入地点、档口、菜品；停用对象和历史评论的处理符合预期。
- 用普通用户和管理员各走一遍点评、复审、举报；不要只看管理入口是否显示。
- 运行小程序静态检查与逻辑测试，再完成微信开发者工具和真机检查。命令见[贡献说明](../CONTRIBUTING.md)。
