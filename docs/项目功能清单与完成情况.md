# 西邮点评家：功能清单与完成情况

检查日期：2026-10-15

检查范围：当前工作区源码、配置、数据库脚本、README 与一期方案。此文档记录代码检查结果，不代表已完成线上部署或真实服务联调。

## 项目目标

一期目标是面向西安邮电大学两个校区的校园美食点评小程序，主流程为：微信登录并选择校区，浏览地点、档口和菜品，查看评分与评论，发布或删除自己的点评，并由内容审核和管理员处理举报。二期交易、失物招领、跑腿和三期树洞、课程评价等目前只是方案与数据库预留，不属于一期待完成功能。

## 一期尚未完成的功能

1. **用户举报入口**：在评论操作中增加举报原因选择和提交反馈，并联调已有举报接口。
2. **管理端界面**：一期方案要求管理员处理举报、人工复审、维护校区/地点/档口/菜品与敏感词；目前只有部分后端 API，没有可供管理员使用的界面。
3. **配置与启动联调**：当前工作区的数据库名与 README/建库脚本不一致；配置文件中包含直接写入的数据库凭证和微信密钥，且 AES 密钥默认值为空。小程序配置的 AppID 与后端微信配置也不一致。需要确认同一小程序凭证、统一数据库名，并通过环境变量配置凭证及非空 AES 密钥，再验证 MySQL、Redis、微信登录与内容审核真实调用。
4. **测试覆盖与内容校验**：本批已有本人点评接口和页面逻辑测试；还需覆盖登录/加密、评论审核与评分汇总、举报去重、管理员权限和真实接口联调。现有资料接口的昵称敏感内容过滤也尚未接入。
5. **日志与上线运维**：落实审核日志归档后再清理、数据库备份与恢复演练、线上 HTTPS/合法域名、日志脱敏、监控告警和发布验证。
6. **上线合规材料**：仓库未见隐私政策、用户协议、备案/类目审核、客服入口等交付材料；应按一期方案的合规清单核验后再提交审核。

- 统一 `application.yml`、README 与 `sql/schema.sql` 使用的数据库名称；确认小程序端与后端使用同一组凭证。
- 清除配置文件中的真实凭证，轮换已写入工作区配置的微信密钥，并改由环境变量注入；为 AES 配置稳定且非空的 32 字节密钥。
- 使用真实 MySQL、Redis 启动应用，逐条验证登录、浏览、提交点评、审核、评分、举报和后台处理。
- 增加关键自动化测试与接口联调记录；补齐审核日志归档、备份恢复、部署、监控和合规材料。
