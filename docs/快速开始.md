# 快速开始与环境配置

更新日期：2026-10-24。

## 本地容器演示

准备 Git、Docker Engine 与 Compose v2+，确认 `docker info` 正常。Windows 使用 Linux 容器。首次构建需下载镜像、Maven 和依赖，宿主机无需安装 Java、MySQL 或 Redis。

```powershell
git clone https://github.com/sheeta2005/XU_speakToMe.git
cd XU_speakToMe
git switch codex/developer-docs-2026-10-23
powershell -NoProfile -ExecutionPolicy Bypass -File scripts/init-env.ps1
docker compose up -d --build --wait
docker compose ps
```

Linux/macOS 使用 `sh scripts/init-env.sh` 初始化，需要 OpenSSL，其余 Compose 命令相同。初始化脚本只创建新的 `.env`，四项密钥/密码独立随机生成，已有文件不会覆盖。`.env` 受 Git 忽略，不得提交。

访问 `http://127.0.0.1:8080/api/v1/campuses`，应返回 `code: 0` 与示例校区。Windows 可继续执行 `powershell -NoProfile -ExecutionPolicy Bypass -File scripts/smoke-demo.ps1`，检查真实数据库、Redis 会话、普通用户权限、点评、人工复审、评分和榜单；脚本会创建并删除一条点评，仅对本地演示环境运行。

服务默认：应用 127.0.0.1:8080、MySQL 127.0.0.1:13306、Redis 127.0.0.1:16379。数据库和普通账号都叫 `speak_to_me`，密码查看本机 `.env`。应用在容器内连接 mysql:3306 和 redis:6379。

如端口占用，修改 `.env` 的 APP_PORT、MYSQL_HOST_PORT、REDIS_HOST_PORT；修改应用端口后同步小程序地址。启动失败查看 `docker compose logs --tail 100 app mysql redis`。镜像或依赖下载超时可原样重试，不必删除卷。

## 打开小程序

1. 使用微信开发者工具导入仓库的 `miniprogram/`，本地体验可使用测试号或游客 AppID，不需要 npm install。
2. 本机调试时，在工具“详情 → 本地设置”启用“不校验合法域名、web-view（业务域名）、TLS 版本以及 HTTPS 证书”。仅用于本地 HTTP 调试。
3. `miniprogram/config.js` 的 develop 默认 demo=true，连接本机 8080。登录页选择演示同学或演示管理员，首次登录选择校区。
4. 同学发布点评后为人工复审；切换管理员，在“我的 → 管理工作台 → 人工复审”处理，随后核验公开点评、评分与榜单。
5. 重新编译小程序可回到登录页切换身份，必要时清除登录缓存。

演示账号固定且共享；启动只补建缺少的账号，不重置已有资料、权限或校区。演示不调用真实微信服务，评论全部进入人工复审，不能视为已通过微信审核。

体验版、正式版不会显示固定身份登录入口。后端仅允许独立 demo Profile；demo,prod、demo,local 等混合环境会启动失败。Compose 端口只绑定回环地址，禁止将演示环境公开部署。

## 配置说明

| 配置 | 说明 |
|---|---|
| APP_PROFILE | Compose 的后端 Profile，默认 demo；真实接入改为 prod |
| AES_KEY | 32 字节随机值的 Base64，与数据配套长期保存 |
| MYSQL_ROOT_PASSWORD | 首次建库管理密码，应用不使用 root |
| MYSQL_PASSWORD | 应用数据库账号密码 |
| REDIS_PASSWORD | 会话、限流与缓存密码 |
| WX_APPID、WX_SECRET | 真实小程序凭证，demo 不需要 |
| APP_PORT、MYSQL_HOST_PORT、REDIS_HOST_PORT | 宿主机访问端口 |
| MYSQL_HOST、MYSQL_PORT、MYSQL_USER | 直接 Java 启动时默认 localhost、3306、speak_to_me |
| REDIS_HOST、REDIS_PORT | 直接 Java 启动时默认 localhost、6379 |
| SERVER_ADDRESS | Java 本机默认 127.0.0.1，容器内设置为 0.0.0.0 |

Compose 自动读取根目录 `.env`；Java、IDE、Maven 不自动将其加载为环境变量。不要把凭证写回跟踪的 YAML。启动检查在业务组件创建前校验 AES；非 demo 还要求数据库和微信凭证，错误信息不输出密钥。

本机开发可复制 `deploy/application-local.yml.example` 到根目录 `application-local.yml`，配置环境变量并激活 local Profile。该文件受 Git 忽略，位于打包资源目录之外，不进入 JAR。

## 真实微信接入

先执行 `docker compose down` 停止演示，保留数据卷和原 `.env`。真实接入必须使用独立 MySQL 和 Redis，不能复用带固定管理员的 demo 数据库。

将 `.env.example` 复制到已忽略的 `.env.real`，设置 APP_PROFILE=prod，填写同一小程序的 WX_APPID/WX_SECRET，并为 AES_KEY 及三个服务密码填入独立随机值。每个可用 `openssl rand -base64 32` 生成，也可在独立新克隆中运行初始化脚本，再将结果保存为 `.env.real`。

```powershell
docker compose --env-file .env.real -p speaktome-real up -d --build --wait
```

不同项目名使用独立命名卷；不要显式复用演示卷。启动前停止演示或调整端口。第六批起真实环境不加载示例学校、菜品或固定演示账号；指定管理员后从管理页维护自己的校区和对象。

微信开发者工具本地项目配置填入真实 AppID，`miniprogram/config.js` 的 develop.demo 设为 false，接口地址匹配后端。体验/正式版必须将 api.example.com 换为自己的 HTTPS 域名，并在微信平台配置合法域名与内容安全所需权限。前后端 AppID 必须一致。

微信账号权限、真实登录与审核、开发者工具渲染和真机行为，需要在自己的账号下另行验收。当前 Compose 面向本地体验和联调；正式部署使用第六批的独立生产模板，迁移、HTTPS、备份恢复、内部监控和回滚方法见[部署与运维](部署与运维.md)。

## 首次真实管理员

先用真实微信普通登录，从带登录态的 GET /api/v1/auth/me 返回中核对自己的用户 ID。部署者通过数据库权限提升指定现有账号，脚本不会创建用户或解封用户。

```powershell
# 123 必须替换为已核对的实际用户 ID。
powershell -NoProfile -ExecutionPolicy Bypass -File scripts/set-admin.ps1 -UserId 123
```

Linux/macOS：`sh scripts/set-admin.sh 123`。核对输出的 id、昵称、role=1、status=1；空结果代表账号不存在。脚本仅接受整数 ID，不根据昵称批量提升，不提供公开提权接口。

使用独立真实联调项目时，让脚本继承对应的项目和 env 文件：

```powershell
$env:COMPOSE_PROJECT_NAME = 'speaktome-real'
$env:COMPOSE_ENV_FILES = '.env.real'
powershell -NoProfile -ExecutionPolicy Bypass -File scripts/set-admin.ps1 -UserId 123
Remove-Item Env:COMPOSE_PROJECT_NAME
Remove-Item Env:COMPOSE_ENV_FILES
```

非容器数据库可用数据库管理工具做等价操作：仅将已确认 ID、status=1 的用户 role 改为 1，随后查询核对。重新进入个人中心会刷新角色。

## 宿主机开发与测试

安装 JDK 21 并配置 JAVA_HOME 与 PATH，确认 `java -version` 输出 21。Wrapper 固定 Maven 3.9.10，使用官方发行地址并校验 SHA-256，无需预装 Maven。前端测试使用 Node.js 22+。

```powershell
.\mvnw.cmd -B package
node --test tests/miniprogram/*.test.cjs
# 在进程环境设置数据库、Redis、微信与 AES 配置后运行：
java -jar speakToMe-app/target/speak-to-me.jar --spring.profiles.active=local
```

Linux/macOS 使用 `./mvnw -B package`。本机直接运行连接 Compose 依赖时，设置 MYSQL_PORT=13306、REDIS_PORT=16379，密码和 AES_KEY 与对应 `.env` 一致。演示可激活 demo，但必须单独使用独立演示数据。

不要在聚合工程直接执行 `-am spring-boot:run`，它会尝试启动没有入口的模块；先 package，再运行 JAR。IDE 可运行 SpeakToMeApplication 并设置相同环境变量。

## 持久化与升级边界

- `docker compose stop` 停止服务；`down` 删除容器/网络但保留命名卷。
- 后续 up 自动校验并执行尚未执行的 Flyway 迁移；demo 示例数据只补缺、不覆盖已有资料。
- `down -v` 会删除数据，只能在明确销毁测试数据时手动执行，不作为排错步骤。
- 更换 `.env` 密码不会自动更换已有 MySQL 账号密码；更换 AES_KEY 不会重新加密历史 openid。请保留原配置并备份。
- 空库由应用执行 db/migration 下的 V1、V2；示例数据只由独立 demo 加载。sql/init 与含删表语句的旧 sql/schema.sql 不用于升级。
- 已有无版本数据库会拒绝直接启动，必须按[存量库接管](部署与运维.md)先备份、停止写入并核验结构，不能重跑建表或删除卷解决。

## 常见问题

| 现象 | 处理 |
|---|---|
| Docker Engine 管道不存在 | 启动 Docker Desktop，确认 Linux 容器与 docker info 正常 |
| `.env` 已存在 | 为保护密钥主动停止，请核对原配置后直接启动 |
| 下载超时 | 检查代理、网络或自行配置可信镜像源，重试时保留卷 |
| MySQL 不健康 | 检查初始化日志和已有卷密码，不使用旧删表脚本排错 |
| 非空库缺少 Flyway 历史 | 按部署与运维文档备份并执行结构核验接管，不启用自动 baseline |
| 微信登录失败 | 检查前端 demo 开关与后端 Profile，或真实前后端 AppID 是否一致 |
| 请求频繁 | 登录每 IP 每分钟 5 次，点评每用户每分钟 5 次，等待窗口恢复 |
| 管理入口缺失 | 查询最新 auth/me，核对 role/status；重启不重置演示账号权限 |
| 真机无法连接 127.0.0.1 | 回环地址只指手机本身，真机需要另配可访问地址与合法域名 |
| Nginx 403 | 历史模板启用 CDN 白名单，不应直接照搬普通反代配置 |
| UnsupportedClassVersionError | 检查 java -version；PATH 可能仍指向旧 Java，统一为 JDK 21 |

参考：[Maven Wrapper](https://maven.apache.org/tools/wrapper/)、[Compose 服务启动依赖](https://docs.docker.com/compose/how-tos/startup-order/)。
