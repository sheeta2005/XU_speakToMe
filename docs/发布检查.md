# 发布检查

本表用于维护者准备版本，不表示现在已全部满足。2026-10-24 的结论：**文档与协作模板可交付，许可证待定，暂不创建正式标签或 Release。** 当前没有正式发布版本。

## 正式发布前必须确认

- [ ] 维护者明确许可证，增加匹配的 LICENSE，核对第三方代码/资源来源及需保留的声明，同步 README 和贡献说明。当前未选择许可证。
- [ ] 落实可用的私密安全报告渠道，更新 SECURITY.md。文档中的 GitHub 私密报告入口尚未确认开启。
- [ ] 按[页面与截图清单](页面与截图清单.md)采集真实运行截图，记录工具/设备版本及提交号。
- [ ] 完成自己的微信账号登录、内容审核和真机验收；为目标部署准备隐私政策、用户协议和用户反馈/处置流程。
- [ ] 梳理已知问题，明确哪些影响本次发布；特别核对校区存在性、自举报服务端约束、昵称审核、会话撤销、多实例词库与评分缓存并发边界。

## 每次候选版本的技术检查

- [ ] 选定代码提交与目标分支，确认各批代码已包含，README 中的克隆分支可以取得这份提交。
- [ ] 在全新目录检出候选提交，初始化独立 .env 与 Compose 项目，从零构建启动；公开校区接口成功，并执行 smoke-demo 的业务验收。不能复用已有工作区密钥或数据卷。
- [ ] 同一提交的 CI 三项全部通过：后端真实 MySQL/Redis、小程序、干净源码容器与运维演练。检查是否有意外跳过项，保存运行链接。
- [ ] 按部署文档验证空库迁移、存量接管、审核归档、备份及空目标恢复、失败发布回退；不要把镜像回滚描述为数据库降级。
- [ ] 页面有变更时，完成日间/夜间、空态、失败重试、普通账号与管理员权限检查，保存真实截图。
- [ ] 检查 Git 差异和导出的交付包，不包含真实凭证、个人配置、备份、归档、证书或用户数据。
- [ ] 核对文档相对路径、命令、API 参数、数据字典和功能状态；CHANGELOG 只记录实际完成内容。

CI 已包含隔离环境的业务与运维检查，但不连接维护者的真实微信、服务器或手机。全新目录验收成功也不等于正式服务器配置已经完成。

## 技术检查通过之后

只有许可证和本次发布范围明确后，才选定版本号，在验收通过的准确提交上创建标签，并写 Release。说明应包含用途、启动入口、变更、兼容性、已知限制和对应 CI 链接，不使用“完美模板”或“生产环境已验证”等无法证明的表述。

合并或更换主交付分支后同步 README、快速开始、贡献说明中的分支指向。在干净目录从最终标签重新安装验收，确认读者按文档获得的是同一版本；失败则修正并重新验收，不把分支成功结果套到未验证标签上。
